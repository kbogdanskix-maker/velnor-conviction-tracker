# Full-App Audit — 2026-09-29

Environment audited: **production** (`https://velnor-woad.vercel.app` + `https://velnor-api.fly.dev`).
Method: authenticated anonymous demo session; every GET endpoint probed across an issuer spread
(US mega-cap, bank/fintech, non-US/ADR, ETF, invalid); `yfinance` compared local-IP vs inside the
Fly machine; then browser-driven UI pass at desktop and 375px.

---

## S1 — CRITICAL: Yahoo refuses the cookie/crumb handshake from Fly's IP

**Everything that needs Yahoo's `quoteSummary` is dead in production for any ticker not already cached.**

Proof, run inside the Fly machine (`fly ssh console --app velnor-api`):

```
info (crumb)                 FAIL -> YFRateLimitError: Too Many Requests
history/chart                FAIL -> YFRateLimitError: Too Many Requests
options (crumb)              FAIL -> YFRateLimitError: Too Many Requests
fast_info                    FAIL -> YFRateLimitError: Too Many Requests
income_stmt (timeseries)     OK
balance_sheet                OK
```

The traceback terminates in `yfinance/data.py:233 _get_crumb_basic -> raise YFRateLimitError`,
i.e. Yahoo declines to issue a crumb at all. The identical calls from a home IP succeed
(`JPM` → full info + 16 option expiries). This is a **datacenter-IP block, not transient
throttling** — it does not clear on retry and serial probes 2.5s apart fail identically.

Surfaces affected (all of `market_data` that touches `.info`):
`get_ticker_info`, `get_company_management`, `get_insider_activity`, `get_dcf_fundamentals`,
`get_options_chain`, screener row building.

Observed user-visible effect:

| Endpoint | MSFT (cached) | KO / JPM / PLTR / SPY (uncached) |
|---|---|---|
| `/markets/info/{t}` | 200 full | `200 {"error":"Info not available"}` |
| `/markets/management/{t}` | 200 | **503** |
| `/markets/insiders/{t}` | 200 | **503** |
| `/markets/fundamentals/{t}` | 200 | `error: Fundamentals not available` |
| `/quotes/options/{t}` | 4 expiries | `expiries: [], currentPrice: 0` |
| `/screener/lookup/{t}` | 200 | **404 "Ticker not found"** |

The demo only looks healthy because the seeded tickers (`ADBE ASML COST MSFT NKE NVDA TSM`)
happen to be cached. `mgmt` and `insiders` have **exactly 2 cached entries each** (MSFT, SOFI) —
so the Company page's management and insider tabs 503 for every other ticker on the planet.

**Fix direction:** the crumb block is not solvable by backing off. Route Yahoo traffic through a
residential/proxy egress, or move these surfaces to a keyed provider. Until then the
"not available" copy should at least not read as if the user typed something wrong.

## S1 — CRITICAL: the screener is missing 18 of the 20 largest US companies

`/screener` returns 1691 rows. The `info:*` Redis namespace holds **exactly 1691** keys — the
screener is not a universe, it is "whichever tickers Yahoo answered for before it started
refusing", silently presented as the whole market.

```
MISSING: TSLA GOOGL GOOG META JPM V KO XOM UNH PLTR WMT MA HD PG JNJ LLY ORCL NFLX
PRESENT: AVGO AMD
```

`screener.py:358` builds the universe from the NASDAQ SymDir (which is complete and correct),
but a ticker whose `info` fetch fails is dropped with no record. Searching the screener for
Google, Tesla, Meta or JPMorgan returns nothing. `/screener/lookup/JPM` → `404 Ticker JPM not found`,
which tells the user the ticker does not exist rather than that we could not load it.

## S1 — CRITICAL: `/portfolios/expense-ratios` is unreachable (dead route)

`app/routers/portfolio.py:773` declares `@router.get("/expense-ratios")` **after**
`@router.get("/{portfolio_id}")` at line 47. FastAPI matches in declaration order, so the literal
path is swallowed by the UUID path param:

```
GET /api/v1/portfolios/expense-ratios
→ 422 {"detail":[{"type":"uuid_parsing","loc":["path","portfolio_id"], ...}]}
```

The endpoint has never been callable in production. Move the declaration above `/{portfolio_id}`.

## S2 — Bank/fintech issuers: 5 permanently blank rows, and their real P&L is dropped

This is the SOFI report from the handoff, now fully diagnosed.

Confirmed **not** a parsing failure. Yahoo genuinely does not publish these for banks — verified
against the raw frames for both SOFI and JPM:

```
SOFI/JPM income_stmt: no 'EBITDA', no 'Cost…', no 'Gross…', no 'Research…', no 'Operating Income'
tk.info['ebitda'] is None for both
```

So `Cost of Revenue`, `Gross Profit`, `R&D`, `Operating Income`, `EBITDA` render as five blank
rows for every bank, plus `Cash & ST Investments` and `Working Capital` on the balance sheet.
`market_data.py:522` does this deliberately ("standardised across companies"), so the blank rows
are a *presentation* choice, not a bug.

**The actual data-capture bug is the other half:** banks report a different P&L that we never show.
SOFI's income statement has 37 rows available, including:

```
Net Interest Income · Interest Income · Interest Expense
Other Non Interest Expense · General And Administrative Expense · Operating Revenue
```

`_INCOME_ROWS` (`market_data.py:473`) is a single industrial-company template with no bank variant,
so the three lines that actually describe a bank's economics are discarded while five empty rows
are drawn. Same class of gap for ADRs: `MC.PA` blanks `R&D`; `ASML`/`PLTR` blank `Net Debt`;
`JPM` blanks `CapEx`; `PLTR` blanks `Dividends Paid` (correct — it pays none).

**Fix direction:** detect the bank/insurer shape (no `Cost Of Revenue` + presence of
`Net Interest Income`) and swap in a financials row template for that issuer type; hide rows that
are all-None rather than drawing an empty line.

## S2 — ETFs return a 200 that the UI has to guess at

`/markets/financials/SPY` and `/VWRL.L` return `200 {"ticker":…,"error":"not_covered", …}` —
no `income`/`balance`/`cashflow` keys at all. Any client doing `data.income.rows` gets a
TypeError rather than an empty state. (Router `markets.py:161`.)

## S2 — An invalid ticker gets a fully-rendered page

`/journey/ZZZZINVALID` → `200 {"ticker":"ZZZZINVALID","name":"ZZZZINVALID","state":"watching",
"state_colour":"neutral", "events":[], …}`. The app will happily draw a Stock Journey for a
security that does not exist, with a fabricated "watching" state and the raw string as the name.

`/sentiment/ZZZZINVALID` → `200 {"neutral_pct":100, "article_count":0}` — reports "100% neutral"
built from zero articles. Same for `VWRL.L`. A confidence figure synthesised from no data.

## S3 — `/markets/insiders/{t}`: `summary` is never populated

`200 {"ticker":"MSFT","summary":null,"transactions":[…25 items]}` — even on the fully-cached
happy path. Worth checking whether the UI renders an empty summary block above a populated table.

## S3 — `/markets/price/{ticker}` requires an undocumented `on` query param

Returns `422 missing query.on` when called bare. Confirm every caller passes it.

# UI audit

Method: every one of the 61 dashboard routes loaded in a same-origin iframe against
production, at 1440px and again at 375px, recording heading, rendered text length,
`scrollWidth` overflow, off-viewport controls and error strings. Interactive flows then
driven by hand.

## What is clean (measured, not assumed)

- **All 61 routes render.** None blank, none threw, none showed an error string.
- **No horizontal overflow at 375px on any page.** (`scrollWidth - 375 <= 0` everywhere.)
- **No out-of-bounds controls.** The 6 off-viewport buttons on every page are the
  off-canvas nav drawer parked at `x:-205`, and the 4 extra on the dashboard are a
  horizontal card scroller. Both correct. This clears two of the four recurring bug
  classes in `feedback_velnor_recurring_ui_bugs`.
- `/alerts` and `/optimizer` are deliberate `redirect()` stubs to `/smart-alerts` and
  `/reflect`, not duplicate pages.
- Statement tables overflow into their own `overflow-x:auto` wrapper on mobile rather
  than widening the page.

## S1 — the Company page opened on a company nobody owns  ✅ FIXED

`company/page.tsx:276` computed `firstHolding` from SWR, then `useState(firstHolding)` —
which captures its argument on the first render only. The portfolio arrives a tick later,
so the page permanently opened on the `"AAPL"` fallback. AAPL is not in the demo portfolio,
and its management/insider data is not cached, so it 503s: the page's whole header
rendered as `—` (sector, insider ownership, institutional ownership, governance decile,
insider net). That is the first impression of the Research section.

Fixed: the first holding is adopted when it lands unless the user has picked a ticker.
Verified — the page now opens on `MSFT`, an actual holding.

## S2 — "Values in USD" on statements that are not in USD  ✅ FIXED

`company/page.tsx:412` asserted USD. Nothing in the stack converts currency, and
`financialCurrency` is **EUR** for both `ASML` and `MC.PA` — ASML being a seeded demo
holding, so every visitor could hit it. Now states the figures are in the currency the
company reports in.

## S2 — rainbow chart palettes on seven surfaces  ✅ FIXED

`design-system.md:176` bans **rainbow categorical colour** and any blue/indigo/purple;
§2 restricts series colour to "teal / gain / loss + zinc neutrals". Shipped anyway in
`AllocationPie` (**on the dashboard**), `sectors`, `compare`, `stock-compare`, `income`,
`expenses`, `subscriptions` — `#a78bfa`, `#a855f7`, `#3b82f6`, `#818cf8`, `#f472b6`,
`#38bdf8` and more.

Worse, `gain` (`#34d399`) and `loss` (`#f43f5e`) were used as *categorical* fills, so a
holding could be drawn in red while being up — colour contradicting its own semantics.

Fixed via a new `lib/chart-colors.ts` (single-hue teal ramp interleaved with zinc), now
shared by all seven rather than four near-identical local copies. Verified in the browser:
dashboard pie fills are `#1AA8BB, #D4D4D8, #157E8C, #A1A1AA, #5EBFCC, #71717A`.

## S2 — the compliance disclaimer rendered below AA  ✅ FIXED

`components/shared/Disclaimer.tsx` used `text-vela-subtle` for both variants. That token's
own definition reads *"faint text — DECORATION ONLY, never readable copy"*. Measured live
at 375px: **3.40:1**, under the 4.5:1 the design system requires.

This is the no-advice guardrail, and ESMA's position is that a disclaimer must be prominent
to count for anything — so this is compliance exposure, not a design nit. Now `vela-muted`,
**measured at 6.69:1** in the running app.

## S2 — 581 uses of raw `text-zinc-500` / `text-zinc-600`  ⚠️ NOT FIXED (too broad to do blind)

The `vela` tokens are correct and pass: `vela-body` #AEB9CC (~9.3:1), `vela-muted` #8A97AC
(~6.6:1). But 581 call sites bypass them for raw Tailwind zinc:

| colour | ratio on `vela-bg` | verdict |
|---|---|---|
| `zinc-500` `#71717A` | **3.84:1** | fails AA for body |
| `zinc-600` `#52525B` | **2.40:1** | fails badly |

On the mobile dashboard alone this produced 24 sub-AA text nodes — allocation percentages,
news headlines, news source names (`thestreet.com` at 2.40:1), the `⌘K` hint at 2.27:1.
This is the "invisible text" entry in `feedback_velnor_recurring_ui_bugs`, quantified.

Worst offenders: `learn` (38), `journal` (30), `TickerDetailModal` (27), `compare` (26),
`fi` (25). **Not fixed** — a blind `zinc-500 → vela-muted` sweep across 581 sites would also
recolour legitimately decorative uses (disabled states, placeholders) and flatten intended
hierarchy. It wants a per-file pass. The contrast probe used to find these is reusable.

## S3 — "Lookout" vs "Watchlist"  ⚠️ NOT FIXED — product decision, needs your call

Confirmed live. The nav renders `/watchlist => Lookout`; the page's own `h1` and breadcrumb
say **Watchlist**.

`nav-structure.test.ts:14` asserts this under the name *"puts the conviction spine in
non-lab groups with the **reframed labels**"*, alongside Positions / Stock Journey / Thesis /
Reflect / Closed & Lessons / Calibration. So "Lookout" is a deliberate conviction-tracker
rename and the **page was never renamed to match** — not a typo.

Per the handoff this is left for you. Either:
- rename the page `h1`, breadcrumb and search entry to **Lookout** (consistent with the
  reframe), or
- revert the nav entry to **Watchlist** and drop that assertion from the test.

`nav-structure.ts:41` and `nav-structure.test.ts:18` are the only two files mentioning
"Lookout" at all.

# Open, not fixed

1. **S1 Yahoo crumb block from Fly** — needs an egress change or a keyed provider. Nothing
   in the app can back off around it.
2. **S1 screener universe** is a partial snapshot missing 18 of the top 20 US companies;
   it will stay wrong until (1) is solved, then needs a rebuild.
3. **S2 `/screener/lookup` returns 404 on a fetch failure** — tells the user the ticker does
   not exist when we simply could not load it. Should be 503, like its neighbours.
4. **S2 invalid tickers render a full page.** `/journey/ZZZZINVALID` returns 200 with a
   fabricated `state: "watching"`; `/sentiment/ZZZZINVALID` reports `neutral_pct: 100` from
   zero articles. Both should 404.
5. **S3 partial insider data is cached as if complete.** `get_insider_activity` raises only
   when *both* sources fail; when just `insider_purchases` fails (as it always does on Fly)
   it caches `summary: null` alongside real transactions for 12h.
6. **S3 581 raw zinc text sites** — see above.
7. **S3 `Lookout` vs `Watchlist`** — your call.
8. Design-system drift on Lab pages: 24 `rounded-xl+`, 29 `shadow-lg+`, `backdrop-blur` in
   10 files. Consistent with the known "Lab long-tail" backlog.
